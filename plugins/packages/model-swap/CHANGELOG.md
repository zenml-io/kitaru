# Changelog

## Unreleased

- Rank only candidates that answered at least 80% of their calls in **Best for**, judge comparability on the calls both the candidate and today's model answered, show answered-of-attempted calls next to each pick, and list under-measured candidates as "Needs more measurement".
- Weight best-mix steps and costs by the recorded traffic each sampled call stands for, for the mix and for today's cost, so a mix that picks one candidate everywhere costs what that candidate costs. Report attempted, answered, failed and not-run calls per step, keep a candidate off a step where it fails on more than a fifth of the calls (overall or on held-out sessions), and say per step whether today's cost comes from the reference replay or the recording.
- Keep each recorded call's `tool_choice`, `parallel_tool_calls`, `response_format` and strict function schemas in rebuilt chat-completions and Responses API requests, or skip the call with a counted reason (`unsupported_request_control`, `unsupported_tool`) when a control or offered tool cannot be sent faithfully. Offer functions without parameters with an empty schema, and keep recorded plain text that is valid JSON as text.
- Hold the spend cap for the request actually sent: reject `extra_body` fields the analyzer sets itself (model, messages, tools, request controls, token limits, `n`, `stream`), reserve the judge's own output limit, reserve room for each retry, and charge replies without usage, timeouts and broken connections their full reservation. Unknown usage is no longer a measured zero cost.
- Shorten oversized tool-call ids consistently in rebuilt requests without changing the recording, and clarify that instructions may be present in user messages when no system or developer message was recorded. Document explicit Responses API selection for GPT-5.6 candidates using tools with reasoning.
- Present the report as stage 1 of 2: a screen that rules candidates out, with full replays graded on outcomes deciding.
- Keep comparisons honest: `system_prompt` per candidate (optionally only on `system_prompt_nodes`) to try a rewritten prompt, a `truncated` failure for replies cut off by the token limit, a blind judge (answers A and B in varying order) rechecked with the order swapped (`judge_check`) and flagged when unstable or when it runs a candidate's model, a note when there is no reference to set a noise floor, and a best mix chosen on half of the sessions and kept only where it holds on the other half.
- Measure candidates against how often today's model matches itself: today's model is the bar and never its own closest match, no cheapest or fastest candidate is named when none is comparable or today's model is too noisy to compare against, and every report ends with the candidates worth a full replay: every candidate except clear failures, plus the cheapest.
- Add a best mix: per step (named by what comes just before a call, which a router can see), the cheapest allowed candidate that answered at least `min_mix_calls` of its calls and behaves within 10 points of today's model, with combined cost against the reference's replay cost. The Compare table shows 95% intervals, and provider errors keep the provider's error message. Candidates can use OpenAI's Responses API (`provider_settings.api: responses`), which OpenAI's reasoning models need for tools with reasoning on. Candidates can declare an `origin` (lab, lab country, host, host region) and runs can set `excluded_origins`, which keeps those candidates out of every recommendation. `repeats` sends each call several times and reports how often any and all attempts matched. Reports lead with tokens per call and say that costs assume the recorded number of steps.
- Find calls a decision model could make: every report classifies sampled calls as decision, partial, or generative with their share of recorded cost, and `decision_candidates` (Jev, Clef, or OpenAI Decisions) answer the decision parts of each call (which tool, and which enum or boolean values) for comparison with the recording, with agreement, failures, cost, and latency. `candidates` is now optional when decision candidates are given.
- Accept decision models as the judge: TypeSafe Jev, Cloudflare Clef on Workers AI, and OpenAI's Decisions API (`"judge": {"kind": "jev" | "clef" | "openai_decisions"}`). The judge's probability that two answers are equivalent is reported per disagreement, rulings are counted as equivalent, different, or unsure, and disagreements are ordered for review with likely different answers first.
- Add the `kitaru/model-swap` analyzer for choosing the right model for an agent. It sends each recorded model call of an import, rebuilt from the recording, to OpenAI-compatible candidate models and names the best candidate per goal (closest to today, cheapest, fastest, best open model). It reports tool-call and answer agreement, provider failure categories, latency, token usage, openness and projected cost per candidate, against the current model as a reference for run-to-run noise. It supports a dry run, a spend cap (strict when candidates set `max_tokens`), a time budget, an optional judge, tool schemas supplied from the agent's code, and a rendered section for `kitaru insight report`.
