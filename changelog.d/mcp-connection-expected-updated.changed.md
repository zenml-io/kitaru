- A `kitaru_connections_manage` update of `env` or `secrets` now requires `expected_updated`, the connection's `updated` time from `kitaru_connection_read`, and any update that sends it is refused with `conflict` if `env` or `default` changed after that read. A change to secrets alone does not move `updated`, so it is not detected: a `secrets` update built on an older read can still restore a secret deleted since, or put back a value rotated since. The check runs just before the write; a change landing between the two is still missed.
