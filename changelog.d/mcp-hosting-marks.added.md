- Kitaru's MCP tool list (`kitaru.mcp.registry.TOOL_SPECS`) now tells a host how to run each tool. Each `ToolSpec` carries its `request_type`, its `result_type`, `run`, the function that does the tool's work with the server state, and `needs_server`, which is `False` for `kitaru_docs_search` and `kitaru_feedback_draft` because they work without a Kitaru server or sign-in. `kitaru.mcp.registry.invoke_tool(spec, state, request)` runs a tool the way Kitaru's own MCP server does: under the state's timeout and concurrency bound, with redaction and the result envelope. Its `passthrough` argument lets a host's own exception types reach the host.
- Add the `stateless` MCP setting (`KITARU_MCP_STATELESS`) for a server that runs as several copies. With it on, `kitaru_failure_matrix_cell` always reads the sessions again. It is off by default, so the local server keeps its current behavior. Copies that share `label_key` (`KITARU_MCP_LABEL_KEY`, at least 32 characters) can each open a cell of a matrix another copy built, including a state whose name redaction masked.
- Add the `custom_viewers` MCP setting (`KITARU_MCP_CUSTOM_VIEWERS`). Turned off, the trace viewer tools serve only the viewers bundled with Kitaru: they read no viewers folder, and no answer names it. It is on by default.
