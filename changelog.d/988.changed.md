- Post-import insight analyzers scan every imported session incrementally while bounding retained evidence, chart categories, and model input. Exact high-cardinality counts can use temporary disk storage; one full session must still fit in memory. Imports run only explicitly selected analyzers and skip analysis when no sessions are completed or failed. Insight listings support an `import_id` filter stored directly on the insight, so task cleanup does not remove this association. The migration backfills existing associations from retained tasks. Plugins in the reserved `kitaru/` namespace and their versions are read-only through the API, regardless of ownership.
- Analyzer entrypoints receive `list[UUID]` session IDs instead of preloaded `SessionView` objects. Each analyzer fetches the metadata or full traces it needs with `KitaruAPIClient`, using the task's existing credentials. The shared runner no longer imports a specific analyzer or loads every trace before invoking custom analyzers.
