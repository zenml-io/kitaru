- Added the `kitaru/model-swap` analyzer (`kitaru-model-swap` package) for choosing the right model for an agent. It sends an import's recorded model calls to OpenAI-compatible candidate models, including local Ollama models, names the best candidate for each goal (closest to today, cheapest, fastest, best open model), and reports tool-call and answer agreement, provider failure categories, latency, token usage, openness, and projected cost per candidate. It supports a dry run, a spend cap, tool schemas supplied from the agent's code, and a reference candidate that measures run-to-run noise. API keys come from environment variables each candidate names, supplied by a `model-swap` provider connection or the worker.
- Added `kitaru insight report --import-id IMPORT_ID --out report.html`, which renders an import's insights as one self-contained HTML file without calling a model. Analyzers can contribute their own section through the `kitaru.report_section/v1` insight metadata key, which is honored only on insights an analyzer task created; the model-swap analyzer uses it for its comparison.
- Added the tool definitions offered to the model to imported `llm_call` nodes, under the reserved `kitaru.tool_definitions` node metadata key and normalized to the OpenAI chat-completions form, in the Langfuse, Logfire, and Phoenix importers. Anthropic `custom` tools are included, and the Phoenix importer also reads Pydantic AI's `model_request_parameters`.
- The `kitaru/model-swap` analyzer accepts decision models as its judge (TypeSafe Jev, Cloudflare Clef on Workers AI, and OpenAI's Decisions API). The judge's probability that a candidate's answer is equivalent to the recorded one is shown per disagreement and orders the disagreements for review, likely different answers first.
- The `kitaru/model-swap` analyzer reports which recorded calls a decision model could make (decision, partial, or generative, with their share of recorded cost) and can try decision models as `decision_candidates` on those calls, comparing which tool and which enum or boolean values they choose with the recording.
- The `kitaru/model-swap` report adds a best mix (per step, named by what a router sees before the call, the cheapest allowed candidate that behaves like today's model there on at least `min_mix_calls` calls), provenance rules (`origin` per candidate and `excluded_origins`, which keep candidates out of recommendations), `repeats` for reading run-to-run noise, and tokens per call with a note that costs assume the recorded number of steps.
- `kitaru/model-swap` candidates can set `provider_settings.api` to `responses` to use OpenAI's Responses API, which OpenAI's reasoning models need to call tools with reasoning on.
- The `kitaru/model-swap` **Best for** summary measures candidates against how often your current model matches itself, never picks today's model as its own closest match, names no cheapest or fastest candidate when none is comparable or today's model is too noisy to compare against, and ends with the candidates worth a full replay: every candidate except clear failures, plus the cheapest.
- `kitaru/model-swap` checks that keep a comparison honest: candidates can set `system_prompt` (optionally only on `system_prompt_nodes`) to try a rewritten prompt (and, as before, `reasoning_effort` to try another effort level) as their own candidate; replies cut off by the token limit are a `truncated` failure, not a disagreement; the judge sees the answers as A and B in varying order, is asked again with the order swapped on up to 20 rulings (`judge_check`), and is flagged when it is unstable or runs the same model as a candidate; a run without a reference says it has no noise floor; and the best mix is chosen on half of the sessions and kept only where it holds on the other half.
- The `kitaru/model-swap` report presents its comparison as stage 1 of 2, a screen that rules candidates out, and says a full replay graded on outcomes decides.
