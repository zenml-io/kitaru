- Added provider connections, a server-side resource that supplies an importer's or analyzer's non-secret environment values and secrets to its task instead of relying on the worker's own environment. Create one from a plugin's `connection_schema` or a provider name with `kitaru connection create`, manage them with `list`, `get`, `update`, `set-default`, and `delete --force`, or through `client.connections` and `POST`, `GET`, `PATCH`, and `DELETE` on `/api/v1/connections`. A provider has at most one default connection, used automatically when an import or analyzer config names none. Select one per analyzer with `connection_id` on its analyzer config, or `--analyzer-connection ANALYZER@VERSION=CONNECTION` on `kitaru session import`. Connection values merge into the import task's environment above the worker's own environment and below `KITARU_*` variables. Creating or updating a connection rejects `KITARU_*` keys and a key set as both an environment value and a secret. Importers and analyzers can declare a `provider` and a `connection_schema` with `--provider` and `--connection-schema FILE` on `kitaru importer register` and `kitaru analyzer register`, which drives interactive prompts on create. The five built-in provider importers ship one. The MCP server exposes `kitaru_connection_read` and `kitaru_connections_manage`, and `kitaru_delete` can delete a connection. Import and analysis tasks carry a `kitaru/provider=<provider>` label, and an API import or analysis task whose plugin declares a connection schema but resolved no connection also carries `kitaru/requires-credentials=<provider>`. A file import resolves no connection, since only an API import talks to the provider.
- Workers select the providers whose credentials their environment holds with `--selector kitaru/requires-credentials=<provider>[,<provider>]` on `kitaru worker start`, and a worker that sets no such selector claims as if it had set an empty one. Either way a worker skips import and analysis tasks that need any other provider's credentials, so a worker selecting nothing only claims tasks whose credentials arrive through a connection or that need none. Set `KITARU_SERVER_EPHEMERAL_WORKER__SELECTORS`, or `server.ephemeralWorker.selectors` in the Helm chart, to add selectors to every ephemeral worker's scope. A label selector's `values` may now be empty, matching only tasks that lack the key, and the compact `--selector KEY=` form sets one.
