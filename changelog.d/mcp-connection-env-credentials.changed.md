- `kitaru_connections_manage` now refuses an `env` key that names a credential, such as `OPENAI_API_KEY`, `HF_TOKEN`, `PGPASSWORD` or `AWS_SECRET_ACCESS_KEY`, and asks for it in `secrets`. `env` values are stored unencrypted and readable by anyone who can read the connection, while `secrets` are encrypted and never returned. Settings that only resemble credentials, such as `MAX_TOKENS` or `AWS_WEB_IDENTITY_TOKEN_FILE`, are still accepted.
- MCP and CLI output now mask a value by the same name rule that `env` refuses: a value under a name such as `AWS_SECRET_ACCESS_KEY`, `PASSPHRASE` or `SIGNING_KEY` is masked, and a setting such as `MAX_TOKENS="4096"` is shown. A name ending in `tokens` counts tokens only after a word such as `max`, `input` or `prompt`; any other, such as `GITHUB_TOKENS`, holds credentials.
- On update, `kitaru_connections_manage` keeps the stored value of any `env` key sent exactly as `kitaru_connection_read` showed it, such as `***` or `Bearer ***`, and accepts a credential-named key only as `***`. A connection created before the refusal can therefore change its other settings by sending back the `env` it read, without overwriting masked values. The refusal and the `secrets` field say that `secrets` on update replaces every stored secret, and an update refuses `***` as a secret value, since it cannot keep a stored secret.
