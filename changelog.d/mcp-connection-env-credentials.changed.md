- `kitaru_connections_manage` now refuses an `env` key that names a credential, such as `OPENAI_API_KEY`, `HF_TOKEN`, `PGPASSWORD` or `AWS_SECRET_ACCESS_KEY`, and asks for it in `secrets`. `env` values are stored unencrypted and readable by anyone who can read the connection, while `secrets` are encrypted and never returned. Settings that only resemble credentials, such as `MAX_TOKENS` or `AWS_WEB_IDENTITY_TOKEN_FILE`, are still accepted.
- MCP and CLI output now mask a value by the same name rule that `env` refuses: a value under a name such as `AWS_SECRET_ACCESS_KEY`, `PASSPHRASE` or `SIGNING_KEY` is masked, and a count under a name such as `MAX_TOKENS` or `input_tokens` is shown even when it is a string.
- On update, `kitaru_connections_manage` still accepts a credential-named `env` key that the connection already holds with the same value, so a connection created before the refusal can change its other settings. Its refusal and the `secrets` field now say that `secrets` on update replaces every stored secret.
