A starter kit for an internal agent factory: the runnable foundation a platform engineer can fork to give their team's developers a way to spin up durable, sandboxed, profile-gated agents fast — with credential isolation and HITL gates wired up correctly. Locally runnable with `bash setup.sh && python stage_N_*.py` and zero external accounts.

## Who this is for

Platform engineers building their org's internal agent platform on top of [Kitaru](/) and [PydanticAI](https://ai.pydantic.dev). The example is intentionally generic — every stage's demo prompt is a throwaway exercising the new tool that stage introduces. The *framework* is the through-line, not a vertical domain. Forking this for your team means swapping the prompt + fixtures + skill markdown; the framework stays the same.

If you'd rather add durable execution to a single function, start with the [Quickstart](/getting-started/quickstart) — that's the smallest possible Kitaru flow. Come back here when you want to see how the same primitives compose into a real agent platform.

## How the tour is organized

The example builds up one capability at a time. Each chapter adds **one tool** or **one architectural primitive**; the library at `agent_factory/` grows monotonically; the per-stage `Profile` gates which capabilities each stage's agent actually exercises. Older stage files stay valid as the library expands.

## Get the code

```bash
git clone https://github.com/zenml-io/kitaru.git
cd kitaru/examples/end_to_end/agent_factory
uv sync
export OPENAI_API_KEY=sk-...
python stage_1_basic_agent.py
```

The full source — runnable stage files, the `agent_factory/` library, mocks, skills, Dockerfiles — lives in [`examples/end_to_end/agent_factory/`](https://github.com/zenml-io/kitaru/tree/develop/examples/end_to_end/agent_factory) on GitHub. The chapters that follow walk through each stage; clone the repo to run them.

## What you'll have at the end

- One `Profile` per agent (Pydantic model: name, system prompt, model string, allowed tools, allowed services, skill source, sandbox-proxy rules).
- A reusable `agent_factory/` library that takes a Profile and produces a durable PydanticAI agent.
- A two-process credential isolation pattern (proxy + worker) wired correctly.
- Typed service handlers for the host-side path; sandboxed `exec` for the shell path.
- Durable human-in-the-loop via `kitaru.wait()` — your flow can pause for hours, the host can reboot, the operator answers, the flow resumes from the same point.

The repo's example README also covers forking guidance ("swap the mock for your real wiki / webhook / skill markdown") and tips for production use (model aliases, memory compaction).
